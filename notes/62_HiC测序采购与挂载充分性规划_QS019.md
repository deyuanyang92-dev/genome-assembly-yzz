# QS019：Hi-C测序采购与挂载充分性规划

日期：2026-11-03。来源：用户明确要求规划指导实际生产的功能。状态：**功能规格与开发计划，尚未实现、未通过生产验证。**

## 0. 用户再次指出的缺口：必须有具体推荐规则

本次修订承认：初稿描述了报告和流程，却没有提供“初装条件→推荐数量”的可执行规则，不能因此声称已具备生产指导能力。第一版需要同时支持两种依据：**特定建库方案的首批测序规划量**，以及**可比实验支持的有效联系目标**。前者可先支持采购，但不能伪装成后者或保证最终结构达标。

### 0.1 已核实、可用于特定方案询价的数量规则

2026-11-03复核[Phase Genomics官方FAQ](https://phasegenomics.com/resources-and-support/faqs-2/)和[Dovetail Omni-C官方支持页](https://dovetail-genomics.com/support/omni-c)，本地网页、文本和SHA256见[来源记录](sources/hic_procurement_rules_2026-11-03/provenance.json)。这是厂家规划建议，**不是独立下采样实验证明的最低充分量**。每个方案独立使用，不拼成通用30–100×范围。

| 方案与适用条件 | 官方规划量 | 按PE150折算的双端测序碱基量 |
|---|---|---|
| Phase方案，基因组<400 Mb | 1亿测序读对 | 30 Gb |
| Phase方案，400 Mb至1.5 Gb | 1.5亿测序读对 | 45 Gb |
| Phase方案，1.5至3 Gb | 2.5亿测序读对 | 75 Gb |
| Phase方案，>3 Gb | 约每1 Gb基因组1亿测序读对 | 约30 Gb × 基因组大小（Gb） |
| Phase方案，初装N50<100 kb **或** contig数>5000 | 在该方案基线增加每1 Gb基因组5000万测序读对；两个条件同时出现只加一次 | 增加15 Gb × 基因组大小（Gb） |
| Omni-C，基因组组装应用 | 官方给30× coverage作为起点、推荐PE150；<3 Gb基因组建议1个文库 | 按测序碱基/G解释为30 Gb × 基因组大小（Gb），此解释须与采购方确认 |

Phase原文在1.5 Gb边界有重叠；边界值先标人工确认，不暗中任取一档。网页没有完整规定raw/clean交付契约及所有倍性分母；上述Gb是读对/深度的名义测序量换算，不声称厂家保证同量clean数据。双hap合集、多倍体分相、非同个体和其他建库产品不自动套用；先记录适用性审阅。不同方案数字不同，也不能据此推断试剂性能优劣。

**明确示例：** 假定1 Gb、单套代表组装、N50=2 Mb、1200条contig，并采用对应Phase方案，则首批询价起点是1.5亿对PE150、45 Gb；若同样1 Gb初装变成8000条contig，则该方案起点为2亿对、60 Gb。采用Omni-C时则按其自身30×起点与厂家确认，不套用Phase的碎片化加量规则。这些是有来源的首次订单起点，尚不是用户样本的充分性结论。

### 0.2 “只有10%有效”时怎样行动

先将10%的分子/分母写清。若确为raw pairs到目标过滤链有效pairs的比例，45 Gb PE150对应1.5亿原始对，10%保留即1500万有效对。**不将45 Gb再除以10%变成450 Gb**：45 Gb原本就是测序规划量，不是有效目标。

只有在另外确认了有效联系目标N及其适用性后，才采用`N/f`反推订单。例如目标经审阅定为5000万同定义有效对、f预计10%，才得到150 Gb；5000万不是本规格默认阈值。若10%只是跨contig比例，不能拿它去换算所有有效读对，更不能拿整库有效率解释跨染色体信号。

### 0.3 真正的充分性规则如何形成

HapHiC现有深度实验显示，在同一作者实验里，1×与0.1×均可有约99.8%挂载率，而syntenic指标约94.49%与81.07%，见[原表复核](sources/hic_depth_production_review_2026-11-03.md)。因此当前可执行的规则是：**拒绝仅凭挂载率采用最低量；不能由该表生成任意HiFi初装都适用的1×、10×或50×有效阈值。** 精确输入N50及目标案例匹配尚待补齐。

推荐状态分为`protocol_starting_order`（特定方案首批规划）、`experiment_supported_order`（有效目标有可比实验支持）、`scenario_only`（人为假设预算）、`needs_inputs`（缺少项目条件）。前两者可填写有条件的首批订单，必须说明依据类型；只有存在有效目标证据时才填写该目标。实际挂载达标另列`structural_sufficiency_status`，不能从订单状态推导。

**生产交付的一句话格式：** “按你提供的G、初装和建库条件，建议首批X Gb／Y亿对；采用哪条规则，预期有效量基于什么保留率；当前支持的是首批采购还是充分性结论；追加、重建或先修初装分别由什么证据触发。”不能用文件清单代替这句话。

## 1. 要解决的生产决策

起点是用户只有HiFi、尚未测Hi-C。功能要回答：为预定的染色体挂载目标，建议购买多少Hi-C原始测序量、预计得到多少同口径有效联系、依据哪些可比实验、预算偏差有多大；数据回来后，判断停止、追加、重建文库或先处理初装问题。

第一版必须在没有用户Hi-C数据时交付有依据的采购方案。浅测和后续深度分析用于更新方案，不能作为生成首份方案的前置条件。不得仅返回“建议50–100×”或“先试测再说”。缺少有效目标的可靠类比时，可使用已审阅适用性的特定方案首批规则；两类依据均不足时仅给待校准情景。

本功能范围是挂载采购和数据充分性；同个体Hi-C直接参与hifiasm分型、多倍体全局分相分别列为附加目标及独立验收，不把挂载成功解释为分型成功。跨个体风险与[QS010](33_跨个体HiC自动评估功能需求_QS010.md)衔接。

## 2. 使用方式与最少输入

用户提供HiFi文件路径、物种/个体信息、希望交付单套代表还是多套hap；未知倍性/核型可登记未知。系统读取已有初装/调查结果，缺少时生成待执行分析任务与资源估计，复用QS001–006。规划功能本身不擅自启动大规模组装。

| 输入 | 用途与缺失处理 |
|---|---|
| HiFi清单、校验值、样本信息 | 识别数据与个体；有效HiFi≥50×按已有项目约定独立检查 |
| 单套G估计及范围、倍性/性别 | 解释规模和未知范围；组装长度不能自动替代独立G |
| 初装FASTA/GFA及版本/哈希 | 取得实际挂载输入跨度S、套数、N50/N90、contig数及长度分布 |
| 污染、冗余/塌缩、杂合与唯一定位线索 | 区分联系不足与初装/定位问题；没有相应分析则标未测量 |
| 挂载目标及可接受未定位/人工校正范围 | 定义“够量”；项目质量目标默认继承笔记23，结构准确性单独列证据 |
| 拟用组织、同个体关系、建库产品/化学版本、读长 | 匹配有效率历史记录，处理酶切/非酶切区别 |
| 预算/报价/交付规则（可选） | 对比可执行订单；注明raw或clean、双端合计Gb或pairs、起订与增购单位 |
| 同类历史QC、试测或已有Hi-C（可选） | 更新原始到有效的转化及独立分子复杂度预测，不作为第一阶段必需输入 |

G、S和相位表示分别保存：例如两套hap联合FASTA可能约2G，论文以S为分母的有效深度不能换成G后保持相同倍数。

## 3. 第一阶段：测序前给出采购方案

### A. 初装需求画像

汇总总跨度、各hap跨度、contig长度分布和短组件比例；关联已知重复/误拼/污染等线索。除N50外保留短尾分布和大组件数。标出初装信息是否足以选择文献类比；高N50不自动降低采购量，疑似错误不自动加量。

### B. 可核查的证据匹配

建立逐实验行的证据表，至少包含：DOI/表页/源码、物种/倍性、输入表示与总跨度、N50及短尾、建库/读长、比对/去重/过滤、计数定义、深度分母、随机抽样方式及重复、软件版本与调参、归组/排序/方向/挂载结果、是否人工校正和真值限制。

候选证据分为“可直接参考”“需明确迁移假设”“仅作机制参考”。分类给出逐项理由，不用未经标定的总相似度分数。与目标不同的单套/多套、过滤链或物种数据可作背景；缺少转换依据时不混为同一深度曲线。每次采用的有效目标必须指向具体证据行及人工审阅结论。

首批复用[HapHiC深度复核](sources/hic_depth_production_review_2026-11-03.md)及[benchmark](11_HiC_scaffolders_benchmark.md)。HapHiC归组Sheet 3和排序/方向Sheet 14联合使用；不能只挑0.02×最低档或近100%挂载率。当前深度实验确切N50尚未核验，须补齐后才能支持按N50直接类比。benchmark的mapped/2密度与HapHiC过滤后深度不自动互换。

### C. 形成有效联系目标与采购情景

路径一：选择有来源的有效联系目标区间，再转换原始订单。目标区间可以覆盖“满足当前交付目标的候选量”和“覆盖已说明不确定性的保守量”；每一端都要有依据，禁止随意统一加倍。路径二：只有特定方案首批规则时，按第0节给初始订单，有效目标留空；没有保留率来源时预期有效量也留空或仅列假设情景。两条路径都缺依据时，输出待校准预算及需补证据。

有效率优先采用同组织/同建库的历史QC；次选有清晰口径的近似项目；再次使用用户或分析者显式输入的假设情景。**10%、20%等数字没有来源时，仅是计算情景，不是预测或默认值。** 经验范围不是统计置信区间。

订单必须给出：首批购买Gb和pairs、预计有效联系范围、可选增购单位、采购/建库口径、资金范围（有报价时）、预期达成的交付条件、未覆盖风险及采用该方案的理由。预算不足时报告预期缺口，不降低科学目标后声称满足。

## 4. 指标与换算契约

分别计数raw pairs、clean pairs、双端可定位pairs、按工具过滤的paired links、按文库规则定义的deduplicated validPairs，以及跨contig联系。每项记录分母、软件/过滤参数和输入assembly身份；不能把这些都叫“有效”。单端BAM记录数不直接当成独立分子数，重复和多重比对规则必须明确。

- HiC-Pro validPairs与HapHiC filtered BAM不视为同一指标；能否转换需实际统计或明确建模依据。
- 尚无染色体坐标时，跨contig不等于跨染色体；同contig近程距离与组装后cis/trans统计分开，不能事先假设正确染色体归属。
- 按顺序条件保留率可连乘；共享raw分母的几个边际百分比不可直接相乘，以免重复扣除。
- Gb固定表示十进制碱基量，明确双端相加；压缩文件GB不等于序列Gb。

设有效读对目标为N，读长为L1/L2，原始读对到**同定义**有效读对的预计保留率为f：

`raw_pairs = N / f`

`raw_Gb = raw_pairs × (L1 + L2) / 10^9`

如果采购保证clean数据而f以raw为分母，则先补齐raw→clean关系或重新定义f，不能套用同一订单数字。已有数据按当前全量去重后的独立联系计入；分批重复不能各算一次。追加深度的f可能下降，需用复杂度预测，不能用当前平均f无限外推。

若证据目标为有效碱基深度C，先用该实验明确的分母S和实际有效读长计算目标pairs；从PE101迁移到PE150时不能把相同Gb和相同分子数视为等效证据。用读对数迁移与用有效碱基迁移的差别须在报告中说明。

**换算示例，仅验证计算：** 人为指定5000万有效对、PE150，f=10%时原始约150Gb，f=20%时约75Gb；5000万本身不是本规格推荐的生物学阈值。500Gb、PE150、f=10%对应约1.67亿有效对；仍需判断联系分布是否满足目标。

## 5. 第二阶段：浅测/交付数据更新建议

将实际QC按上述指标契约解析，检查与历史有效率口径相符；报告重复、唯一定位、有效连接及可解释的距离分布和不同长度contig的联系覆盖。以真实数据更新采购情景及分子复杂度外推，给出以下动作及可核查原因：

| 动作 | 所需判断依据 |
|---|---|
| 继续原计划/追加测序 | 仍缺结构支持，且新增测序预期可增加足够独立有效联系 |
| 改善或重建文库 | 去重后新增分子趋于耗尽或建库异常；不能仅凭有效率10%定失败，须区分定义与原因 |
| 先处理初装/比对问题 | 缺序列、冗余/塌缩、样本不匹配或定位歧义解释了主要损失；报告证据 |
| 停止增加测序 | 既定交付条件获得支持，数据梯度改善有限且争议区域的限制不是总量不足 |

改过滤参数、换初装或换工具后重算口径，不能将保留量上升直接称为文库改善。报告版号记录新信息导致建议变化的原因。

## 6. 第三阶段：挂载充分性复核

固定同一初装、软件和过滤规则，选择资源预算内的深度档及随机重复，独立目录执行。比较分组、邻接、方向、未定位长度、短contig救回、联系图和逐连接支持/冲突；结合目标个体HiFi核查能够跨越的候选断点。HiFi不能跨越的区域标未知，而非无支持即判错。

评价稳定性与正确性分开：没有真值时不输出绝对结构准确率；所有深度得到相同错误结构也可能稳定。结构阈值/平台期判定阈值需预注册、来源及校准状态，首版不编造通用默认门槛。挂载率98%/99%等项目目标不能替代方向/误连的判断。

## 7. 报告与结构化输出

报告先给采购/追加/停止动作，然后给依据。用户能直接拿报告与测序公司核对：

1. 推荐原始或clean Gb、PE长度、pairs与首批/增购方案；正式建议或待校准情景状态。
2. 对应有效联系目标、保留率区间及来源、规模分母和套数、所选证据及迁移假设。
3. 成本与预计交付条件、关键风险、补测/重建/停止条件。
4. 样本与输入哈希、工具/数据库、原始QC和执行日志链接。

结构化结果至少分开保存`recommendation_status`、`recommended_order`、`order_basis_type`、`structural_sufficiency_status`、`scenarios`、`evidence_matches`、`missing_evidence`、`next_action`及每一项理由。订单可依据匹配实验或适用的特定方案起点；只有假设情景时`recommended_order`为null，不能自动选为推荐。见[输入示例](../templates/hic_procurement_project.example.json)、[报告模板](../templates/hic_procurement_report.md)。

## 8. 开发顺序与验收

| 阶段 | 可独立验收的交付 |
|---|---|
| V1，测前规划，优先实现 | 接收已有调查/初装；人工审阅的论文证据登记与匹配理由；单位/分母校验；预算情景和可追溯推荐报告；无Hi-C也能使用 |
| V2，实际QC更新 | HapHiC输入链与至少一种文库QC口径适配；同分母有效率；复杂度预测与追加/重建建议，保留预测范围 |
| V3，深度梯度与挂载复核 | 独立缓存及随机重复；结构变化表、审图交接；结合证据建议停止/追加；与QS012交付闭环联通 |

V1前置补学：补齐HapHiC深度实验N50及运行配置、至少一类与目标输入相近的真实项目证据，并保留不匹配因素。不能先写死剂量公式再补引用。QS001/002供应G与HiFi调查，QS006供应可恢复编排，QS008/010供应跨个体评估，QS012供应挂载校正；无需重写上游算法。

必须验收的案例（后续实现时执行，本次未执行）：

- 没有Hi-C但有HiFi/初装，仍生成含依据来源的采购报告；没有可靠有效目标时可给适用方案的首批规划；两类依据都没有时明确输出待校准情景。
- 特定Phase方案1 Gb/1200条/N50 2 Mb输出1.5亿对、45 Gb的首批规划；8000条时输出2亿对、60 Gb。方案或相位表示未匹配时不自动执行此规则；两个碎片化条件同时出现不重复加量，1.5 Gb边界转人工确认。
- 原始订单45 Gb、10%保留输出1500万有效对的条件预测，不能倒算450 Gb。协议首批采购状态不能自动变成结构充分性通过。
- raw/clean、read/pair、Gb/文件GB、G/S、单套/两套hap、PE101/PE150混用时阻止直接换算并说明缺项。
- 上述5000万有效对、10%/20%和500Gb示例计算正确；f为空、0、负数或>1不产生可执行推荐。
- 分批全局去重、顺序条件率与边际率、有效率随深度下降，均不重复计数或盲目线性追加。
- 同挂载率而排序/方向质量差的HapHiC表格案例不得判“满足生产”；低有效率由文库与比对问题分别解释。
- 不同倍性/过滤链/软件版本的文献不会混作一条可比深度曲线；没有真值不输出绝对准确率。
- 与人工专家审阅的历史项目回放比较；记录预算预测误差、独立联系数误差和错误追加/停止案例。再用公开真实数据验证单套与多套输入，不能用换算测试代替生产验证。

完成本规格不增加已实现功能、真实Hi-C实验或生产验收数量。
