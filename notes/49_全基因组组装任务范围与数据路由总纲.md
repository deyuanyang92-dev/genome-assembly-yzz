# 全基因组组装：任务范围与数据路由总纲

记录日期：2026-11-02。依据：用户明确纠正“要求是全基因组组装，自然包含各种数据类型”。本页规定学习和开发范围，不代表下列路线均已学习完成、实现或实测，也不是本轮新增文献研究。

## 总范围

本项目目标是能够依据物种、数据组合和交付目标指导全基因组组装及软件开发。不能将其缩减为HiFi/ONT流程，不能把二代或参考辅助路线描述为用户后来额外添加的例外。已有笔记对HiFi与Hi-C较深入，是目前的学习分布，不是任务边界。

## 数据按作用建模

| 作用 | 应覆盖的数据 | 路由前要检查什么 |
|---|---|---|
| 构建目标DNA序列 | 普通二代WGS（单端/双端）、HiFi、其他PacBio长读如CLR、ONT不同读长/精度类型；历史Sanger/BAC资源按需要接入 | 有效量、错误模型、读长/分子跨度、文库、样本身份、核/细胞器/污染成分；不把不同平台模式混用 |
| 混合组装与校正 | 二代＋长读、HiFi＋ONT、多文库/多批次等 | 选定软件是否支持具体组合，校正前后收益，缓存与来源；不因有更多数据就全部混入 |
| 长程连接与结构 | Hi-C/Omni-C、mate-pair、linked-read、遗传连锁图谱、光学图谱、核型/细胞遗传证据 | 各自的建库/观测机制、独立性、分辨率及个体来源；普通PE不等同于Hi-C |
| 参考辅助 | 同种或近缘参考、多个参考、已有contig/scaffold/图 | 参考质量、相似性、核型和重排、来源偏差；区分排序、切断、补洞与共识 |
| 分相与倍性 | 亲本/家系、目标个体杂合位点、长读与Hi-C、倍性信息 | 能否支持目标个体的相位；二倍体与多倍体分别设计，跨个体不能默认共享相位 |
| 注释与辅助验证 | 二代RNA、三代RNA、蛋白同源证据、重复序列及谱系库 | 是注释/评价证据，不作为普通DNA-WGS的替代输入；登记组织、条件、个体及数据库版本 |

范围以能力覆盖为目标，不要求所有历史软件同等深读。每种路线选择仍维护或有充分复现价值的候选，分别记录手册、版本/commit、关键源码、issues、运行和未解决缺口。

## 每种路线都必须有完整链条

样本与数据识别 → 质控/污染检查 → 基因组大小、杂合度、重复与数据充分性调查 → 初装/分相或参考辅助 → 按证据决定去冗余及校正 → 条件适用的挂载 → 人工校正 → 多维质量评价 → 注释及交付。

阶段是否适用必须说明原因。例如无长程数据可交付草图，但不能跳过结构证据不足的说明；去冗余不是所有组装必经步骤；注释另设输入与验收。Juicer是Hi-C处理分支的候选组件，BUSCO是完整度评价组件，不能因不是组装器就漏出软件依赖清单。

## 路线选择与验收约束

- 先问“数据能支持什么结果”，再选软件；不能先选hifiasm再要求所有输入适配它。
- 支持从头、混合、参考辅助及现有组装改进；参考坐标共识单列交付类型，不能冒充独立从头组装。
- 用户已规定的有效HiFi≥50×适用于HiFi路线。其他平台/文库各自报告充分性，不把50×机械套用到ONT、Hi-C或二代，也不将二代碱基折算抵扣HiFi门槛。
- 草图、染色体尺度、单倍型解析和T2T是不同目标；适用质量目标与结构证据逐项验收，缺数据标记未知或未达，不随路线改变而静默放宽高标准。
- N50、BUSCO、k-mer、覆盖、污染、结构和分相分别评价；记录实际使用的数据及证据是否独立。
- 物种基因组大小、重复、杂合度、倍性、性染色体和研究目的参与决策；不能承诺某个平台或某覆盖量对所有物种都充分。
