## 怎样判定“完整复现”

有 GitHub 不等于论文已能一键复现。至少要逐项找到：原始数据 accession 与样本信息、参考序列版本、下载与校验和、软件/容器固定版本、参数、随机种子、作业环境、评估真值、原始结果及绘图脚本。源码仓库可能仅提供工具，或仅保留研究者集群上的作业模板。

YaHS 官方 `scripts/run_test.sh` 和 hifiasm README 的小数据适合检验安装及输入输出通路，不能证明重现了论文全部性能结果。基准仓库提供多阶段脚本，但仍需迁移 Slurm、module 和绝对路径。Galaxy `.ga` 工作流携带工具 ID 和连接，执行还依赖对应 Galaxy 实例的工具版本和数据。镜像使用 `latest` 时必须额外记录 digest，源码 commit 无法固定镜像内容。

## 后续比较实验的设计依据

以下是结合源码和论文范围形成的本项目设计建议，尚未执行：同一组 contigs、同一份有效 Hi-C 接触，比较 YaHS、HapHiC 以及有需要时的 3D-DNA。保留未挂载基线；分别测试碎片化和近染色体连续度输入；区分 primary、单条 hap 和合并多条 hap。所有工具统计未挂载序列和失败作业，不通过丢弃难例美化结果。已知参考应尽量来自同一样本；不同个体的真实结构变异不能全算成组装错误。核型和参考序列使用情况也应写入报告，以说明是否引入额外先验。

选择适合数据的工作流，比把不同论文中的最好数字直接并列更有解释力。对环节动物，应先获得基因组大小、杂合度、污染和倍性的证据，再决定 primary 去冗余还是双单倍型组装。
