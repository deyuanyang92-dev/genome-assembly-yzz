# 去冗余、质量评价和流程选择

日期：2026-11-01。原始文献见 [论文地图](10_论文与复现资源地图.md)；以下命令为使用模板，尚未在用户的样本上执行。

## purge_dups：按深度与自比对判断冗余

直接阅读 [官方流程](https://github.com/dfguan/purge_dups) 和本地 README，并成功编译 `src/`。核心是把覆盖深度与 assembly self-alignment 结合，找出 haplotig 和重复区域；不是按序列相似就直接删除。通常用于希望得到一套 primary 表示、但残留等位冗余的情形。

```bash
# HiFi 示例；其他平台按对应 minimap2 preset 和官方参数设置
minimap2 -x map-hifi -t 32 primary.fa hifi.fastq.gz | gzip -c >reads.paf.gz
pbcstat reads.paf.gz
calcuts PB.stat >cutoffs 2>calcuts.log
split_fa primary.fa >primary.split.fa
minimap2 -x asm5 -DP -t 32 primary.split.fa primary.split.fa | gzip -c >self.paf.gz
purge_dups -2 -T cutoffs -c PB.base.cov self.paf.gz >dups.bed 2>purge_dups.log
get_seqs -e dups.bed primary.fa
```

先画覆盖分布并审阅自动 cutoffs，结合预期基因组大小判断；低杂合、重复区、异常覆盖或污染都可能使自动阈值不可靠。minimap2 的参考索引需避免把一次覆盖估计分裂成不能按预期汇总的独立索引块，按基因组规模设置 `-I` 并检查日志。`get_seqs -e` 仅对末端进行相应处理，是较保守的提取选择；输出名称以该版本帮助为准。

去冗余前后记录总长度、BUSCO 完整/重复变化、可靠 read k-mer 保留、被删区间的覆盖和同源证据。重复 BUSCO 降低但真实序列大量丢失不是成功。真实的多倍体同源染色体和完整两条 hap 不能当成应删除的 haplotigs；是否去冗余取决于期望的生物学表示。

## Merqury：序列和分相质量，不能替代结构评价

已读 [官方 README](https://github.com/marbl/merqury)、`merqury.sh`、`eval/qv.sh`、`eval/spectra-cn.sh`。准确 reads 的 k-mer 数据库为参照，检测 assembly-only k-mer（错误候选）及可信 read k-mer 在组装中的覆盖；亲本特异 hap-mer 可评价分相。

```bash
# MERQURY 应设为实际安装目录，meryl/R 等依赖需在环境中
# k 要根据基因组大小、重复与测序错误选择，不固定套一个值
meryl k=21 count output reads.meryl accurate_WGS.fastq.gz
bash "$MERQURY/merqury.sh" reads.meryl assembly.fa sample
# 两条 hap 的联合/分别评估
bash "$MERQURY/merqury.sh" reads.meryl hap1.fa hap2.fa phased_sample
```

`accurate_WGS` 应是同一个体、覆盖和准确度足够的全基因组数据；Hi-C 有建库与接触偏倚，不能无条件替代 WGS 来估计全基因组 k-mer 完整性。用 HiFi 本身可评价，但要说明参照与组装数据并非独立；独立短读长数据有不同的验证价值。

源码 QV 估计使用 assembly-only k-mer 比例 f，按 k 换算碱基错误概率：`e = 1 - (1-f)^(1/k)`，`QV = -10 log10(e)`。这依赖 k-mer 错误模型和参考 reads 的质量；无 assembly-only k-mer 时的极大 QV 不能解读为基因组绝对无误。完整性也须说明可信 k-mer 阈值及单 hap/两 hap 联合统计口径。

审阅 `.qv`、完整性、spectra-cn 图、若有亲本的 hap-mer 图和 phase block/switch 指标。低拷贝峰缺失可能提示丢失，异常重复峰可能提示残留等位重复，但应结合污染、覆盖和图证据解释。源码 shell 没有统一严格错误处理，有些子任务在后台运行，不能仅凭入口退出码 0 判定成功，要检查各阶段日志和必需结果。`-c` 的 homopolymer compression 有特定适用范围，不能把 Verkko 路径里的 HPC hap-mer 直接当成普通 QV 库。

## Verkko：补充长距离证据以解决图歧义

本次固定 [v2.3.2](https://github.com/marbl/verkko/tree/v2.3.2)，读 README 并结合已有 [notes/06](06_Verkko.md)。核心由 HiFi 的 multiplex de Bruijn graph（MBG）、ONT 超长 reads 的图比对/解缠、rukki 路径选择及共识组成。hifiasm 的 string graph 与它的图模型不同，不宜只按命令长短比较。

```bash
verkko -d assembly --hifi hifi.fastq.gz --nano ont_ul.fastq.gz \
  --hic1 hic_R1.fastq.gz --hic2 hic_R2.fastq.gz
```

该模板未运行。检查此版本依赖：源码下载需要 submodules；本地只下载顶层源码，不代表程序完整安装。README 对 Snakemake 要求为 >=7、<8.0.1。HiFi 为必需输入，超长 ONT 强烈推荐；Hi-C、亲本 hap-kmer 与 Pore-C 有互斥/适用限制，不把所有选项叠加。README 不支持一般多倍体路径，haploid+Hi-C 也有限制。Hi-C 整合是后续 Verkko2 发展的能力，不能把当前 v2.3.2 所有功能都归于 2023 原始论文。

## VGP 与 Sanger 流程：学习任务图和信息交接

直接阅读 Sanger `subworkflows/local/scaffolding/main.nf`：两条 hap 分开进入 Hi-C mapping 和 YaHS 子流程，再生成对应统计与预审阅材料。这个版本流程入口使用 Hi-C CRAM；不能把独立工具的 FASTQ 命令当成 Nextflow samplesheet 的等价输入。

Galaxy IWC 当前检出 SHA `8da2120`，与原仓库旧笔记中的 `d9ec763` **不同**。检查 VGP4/VGP8 的 `.ga` 后，可见工具 wrapper 版本，例如 hifiasm `0.25.0+galaxy3`、YaHS `1.2a.2+galaxy3`；这不等于本地 YaHS 1.2.2。阅读工作流时需要追踪连线、嵌套子流程、输入类型、参数默认值与测试 fixtures，不能只数有哪些工具图标。本次未在 Galaxy 执行，也未重新执行 Sanger 全流程。

## 结构质量与最终选择

针对 HiFi 草图可先以 YaHS 建立公开示例已验证的基线；若输入涉及多条单倍型或等位误连，结合 HapHiC 的模型设计对照；若长重复需要超长 reads 解决，可评估 Verkko。以上为本项目推断，尚未用用户样本比较性能，不宣称某一工具普遍最好。

接触图中跨染色体强块、连接点信号突变、局部反向信号可能提示错误，但重复区、着丝粒聚集和真实生物学接触也会产生结构，需多证据核对。人工修改应记录坐标、证据、操作前后结果、原始及修改后 AGP。保留未挂载 contig，避免用删序列换取更高的“挂载率”。结构、序列、分相、完整性和污染应分别给出指标，不能由一个 N50/QV 总结全部质量。
