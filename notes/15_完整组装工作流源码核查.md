# 完整组装工作流：重新分类与源码核查

核查日期：2026-11-01。本文回应“找像 sanger-tol/genomeassembly 这样的流程”。统计对象须实际串联原始 reads、组装、挂载和评价；允许部分步骤按输入条件跳过。完整指分析链路，不意味着自动完成专家人工审阅、T2T 或基因注释。

**已下载并核查 6 套此类工作流/工作流集合；本机端到端运行 0 套。** 本轮没有 Nextflow/Snakemake 可执行程序，也没有用户的测序数据。旧笔记中的另一台机器测试不计入本机实测。Verkko 另列为组装核心工作流，Juicer/3D-DNA 为 Hi-C 子流程；hifiasm、YaHS、HapHiC 等不再计入完整流程数。

## 2. 不能用“都调用 YaHS”代替理解流程

Sanger 的核心抽象是 **dataset → assembly specification → stage**。`NUCLEAR_ASSEMBLY` 按 stage 调用 hifiasm、purging、polishing、scaffolding，再把每阶段组装送给 GENOME_STATISTICS，并生成 stage/spec 索引。同一数据的不同组装方案可以复用共享阶段。应阅读 stage 的选择与数据交接，而不是把四个工具名抄成线性命令。

nf-core 的 Hi-C 分支按 `hic_aligner` 在 bwa-mem2/minimap2 间选择，接 AddOrReplaceReadGroups、MarkDuplicates、FAIDX、YaHS，再 BGZIP，重新做 QC，按配置可做 Liftoff。**仅在 samplesheet 提供 Hi-C 不等于已启用挂载**：核对 `scaffold_hic`、`hic_F`、`hic_R`、`hic_aligner`。通用 bioSkills 的 rnaseq 样本表不能替代该流程 schema。

EBP-Nor 的分型分支不直接把全量 Hi-C 分别比到两套 hap：先构建各 hap 的 meryl 库，求 hap 特异 k-mer，`meryl-lookup -exclude` 排除含另一 hap 特异 k-mer 的 reads，再分别比对。它不等于“所有保留 read 都已准确分型”，因为不含判别性 k-mer 的 read 也可保留。后续 `prepare_hic` 最终**重新按 read name 排序**再交 YaHS，这与直接传坐标排序 BAM 有实质区别。单倍体分支使用原始 Hi-C。

CLAWS 的 `postpolishing.smk` 按是否 purge、是否 tigmint、是否对 hifiasm 外部 purge 选择实际输入；`deepseq` 与 `run_yahs` 决定文库 QC 或挂载。只列 README 的默认工具链，会漏掉这些条件。独立的 `scaffolding_rules.smk` 中还存在特定样本的 10X 规则，不能把它当成全部 Hi-C 实现。

## 3. 可复现使用入口

以下是**准备完成后可用的入口模板，未在本机执行**。必须先固定源码、引擎、容器/环境、参数与数据库校验和。

```bash
# 在学习库根目录；文件路径由项目实际数据填写
nextflow run ./pipelines/sanger-tol_genomeassembly \
  -profile singularity \
  --genomic_data /absolute/path/genomic_data.yaml \
  --assembly_specs /absolute/path/assembly_specs.yaml \
  --outdir /absolute/path/results_sanger -resume

nextflow run ./pipelines/nf-core_genomeassembler \
  -profile singularity -params-file /absolute/path/params.yaml \
  --input /absolute/path/samplesheet.csv \
  --outdir /absolute/path/results_nfcore -resume
```

本地 checkout 已固定 SHA，所以不在本地路径命令再加远程 `-r`。Sanger 从 FASTQ 转 Hi-C CRAM 的操作和 specs 示例见笔记01；nf-core CSV 列与可选开关见笔记03和当前 schema。Galaxy 使用 `.ga` 对应的输入 label/collection 类型导入；不能给 VGP8 的单 hap 入口塞入未区分的两套 hap。

CLAWS 先检查 `bin/create_config_assembly.py -h` 的参数定义，生成样本配置和资源 spec，再对照原笔记04修改。EBP-Nor 要同时修改生物参数 `config/asm_params.yaml` 和执行 profile `config/config.yaml`：其中 `aves`、`TTAGGG`、示例 taxid、`/cluster/projects/nn8013k/` 都不能照搬到环节动物。Snakemake 6/7 的 `--cluster` 模板不能直接套到 Snakemake 8/9；Colora 则使用其当前 README 的部署方式。

## 4. 容易误判成功的情况

- EBP-Nor 在 Snakefile 顶层执行 mkdir/软链接，解析阶段就可能写文件；dry-run 应在隔离工作目录。部分 oatk/curation 规则使用 `|| touch`，因此文件存在不证明结果有效；检查大小、格式、日志及预期轨道。YaHS 后删除 `.bin`，若需要该中间文件做其他 curation，要事先调整保留策略。
- 生物学数据/数据库不适配，即使工作流退出码为 0，也不能算成功。BUSCO 谱系、NCBI taxid、Hi-C 建库方案、端粒序列与倍性都属于项目配置。
- 组装、分型、挂载、污染识别、人工校正、基因注释是不同交付；不能用某一个 `final.fa` 或 N50 宣称全部完成。

## 5. 学习结论与证据层级

Sanger 用于深入研究可组合阶段和复用，VGP 用于去污染与人工校正闭环，Colora 用于阅读较紧凑且有测试数据的论文工作流；nf-core、CLAWS、EBP-Nor 用于比较适用数据与工程取舍。这个选择依据功能与可复现接口，**没有检索引用数据库，不宣称六者均为“高引论文流程”**。

论文与流程须对应版本：[VGP Nature 方法论文](https://doi.org/10.1038/s41586-021-03451-0)可支持方法体系，不能证明今天任意 IWC 提交已经复现；[Colora Bioinformatics 方法论文](https://doi.org/10.1093/bioinformatics/btaf175)与当前 main 也可能有版本差异。论文发表、CI badge、提供测试数据、本机实测是四种不同证据。
