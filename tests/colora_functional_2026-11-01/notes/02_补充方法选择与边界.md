# 方法选择与学习边界

此表结合原学习库及本轮官方资料核查。用于明确输入、产物和验收；不是全工具benchmark，不宣布一种软件普遍最优。目标物种真实数据尚未开展端到端运行。

| 任务/条件 | 方法或工具入口 | 关键判断与应保存的证据 |
|---|---|---|
| 样本与原始质控 | FASTQ/平台元数据，fastp，NanoPlot，seqkit | 先区分DNA/RNA/Hi-C、个体、文库及处理状态；读长/碱基量/质量分布不能互相替代 |
| 基因组调查 | KMC/GenomeScope2，Smudgeplot，lrge | G、杂合、重复和倍性有假设与不确定性；D/G须明确有效核数据与单套G口径 |
| 短读长组装 | SPAdes等按场景评估 | 官方SPAdes以Illumina为主、长读为补充，包含多种专用模式；不能由小基因组/细胞器成功推论适合复杂高杂合动物核基因组 |
| HiFi与分型组装 | hifiasm，按资料评估Verkko/上游完整流程 | 产品可能为primary/alternate或hap1/hap2；按输入模式定义角色；跨个体Hi-C分开做风险与对照 |
| ONT主数据组装 | Flye及适用长读组装器 | Flye官方说明二倍体通常输出折叠的嵌合单套表示，不能只因文件完整就当作两个相位明确的hap；模式与读段精度匹配 |
| 去冗余 | purge_dups等诊断后执行 | 比较拷贝谱、深度、基因/独有k-mer保留；移除记录可追溯，不能以BUSCO D下降当唯一目标 |
| 污染筛查 | FCS-GX，分类/覆盖等辅助证据 | 记录taxid、数据库、命中与实际清理操作；本轮Colora功能配置跳过此项，不生成污染合格结论 |
| 抛光 | NextPolish或NextPolish2按输入选择 | 官方将二者定位为不同适用场景的补充；NextPolish2使用HiFi回贴及短读k-mer，不能在缺少这些输入时机械加入；校正前后独立检验并保留hap一致性 |
| Hi-C挂载 | Arima/适用比对处理→YaHS/HapHiC等 | 保留文库、排序/去重/MAPQ、AGP与FASTA版本；人工校正后重比对和评价，不将自动挂载等同染色体结构真值 |
| 序列与结构评价 | Merqury、BUSCO、回贴、图/Hi-C与gap清单 | N50、BUSCO、QV、序列完整性和结构正确性分别解释；同一数据的内部一致性与独立验证分开 |
| 重复序列 | RepeatModeler/RepeatMasker等 | RepeatMasker默认mask为N；用于基因预测时按后端要求明确软掩蔽参数。自建库/分类库、mask坐标和FASTA版本保存；不能自动删除重复区域 |
| 基因结构注释 | BRAKER、Helixer、EviAnn、RAGNAROK/REAT–Minos等候选 | 比较证据与模型适用类群；DNA不是转录证据；结构、异构体、ncRNA和功能层分开，后端需原生示例与目标类群验证 |
| 比较基因组 | OrthoFinder、家族HMM、基因组补查、共线性 | 一gene代表异构体及hap关系去重；orthogroup不自动等于一对一直系同源，阴性有unknown状态，缺失需要补查 |
| 系统发育 | 直系同源筛选→MAFFT→模型/基因树→IQ-TREE/物种树 | 检查旁系同源、组成/饱和/缺失、基因树冲突；串联分区和coalescent问题分开；高支持率不能证明同源筛选正确 |
| 低深度genome skimming | 细胞器/重复或高拷贝标记专用回收 | 可以完成这些目标而仍远不足核基因组完整组装；各类核标记的覆盖和偏倚单独评估 |

## 本轮新增阅读得到的具体选择限制

NextPolish2官方一般流程需要HiFi BAM及短读k-mer，且指出短读质量影响过度校正，QV变高未必等于真实错误更少。因此抛光是有输入与证据条件的分支，不是所有HiFi初装的默认补丁。本文没有运行抛光，也没有证明测试数据需要校正。

RepeatMasker的mask结果不改变序列坐标，但默认N替换与软掩蔽含义不同；必须记录调用。官方允许自定义`-lib`，类群查询的FamDB/分区另配，不能只装程序就认定已经具备物种适用重复库。

OrthoFinder文档区分HOG与传统聚类输出；固定版本再写解析器。IQ-TREE官方分区教程区分共享、比例和独立分支长度模型；选择模型和处理基因树冲突要分别记录，不能用默认命令代替研究设计。

## 注释入口的版本复核

本轮再次检查旧BRAKER官方README：其顶部明确deprecated并指向BRAKER4。旧BRAKER3仍可作为固定版本复现基线，不能写成当前唯一默认入口。BRAKER4需结合已有40、43号笔记中固定配置与源码判断模式，不能把新的编排版本等同已经有独立准确率benchmark。

EviAnn发行README强调证据路线，计时从RNA已比对的输入起算，不能与包含原始RNA处理的全流程时间直接比较。无本物种RNA的近缘迁移场景仍需相关物种转录本/蛋白，并有平均DNA相似度条件；不能把任意远缘蛋白单独投射说成完整EviAnn注释。

官方来源：https://raw.githubusercontent.com/Gaius-Augustus/BRAKER/master/README.md ; https://raw.githubusercontent.com/alekseyzimin/EviAnn_release/main/README.md 。这里只复核状态及输入/计时边界，未声称全文手册及所有分支已实测。
