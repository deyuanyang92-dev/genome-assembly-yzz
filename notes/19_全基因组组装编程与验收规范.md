# 全基因组组装编程与验收规范

记录日期：2026-11-01。用途是把已读流程转成后续开发约束；这是本项目的设计规范，不是 Sanger 或其他工具的现成配置格式，也不表示已实现完整软件。生物学判断配合[21 基础与质量判断](21_组装基础与质量判断.md)，源码证据见[20](20_源码追踪与能力验证.md)。

## 1. 先定义产品，再选执行流程

明确物种、倍性、核型、样本个体、数据类型和交付目标：primary、primary/alternate、两个局部分型 assembly、染色体分型 assembly 或染色体级 scaffolds。这些产品不能仅凭 FASTA 文件名互相替代。Hi-C 是否同一个体必须作为决策字段，未知不能自动当作相同。

六套流程用于比较和借鉴；一次实现选定一个固定版本的执行主干，再封装输入、审计和评价。不要把 Galaxy `.ga` 当 shell 脚本，不要把不同工作流同名参数互换。Sanger 的 CRAM/spec 输入和 nf-core 的 samplesheet/开关不同；二者适用范围也不同，见15。当前没有依据为未知物种指定通用最佳流程。

## 2. 程序必须保存的对象

| 对象 | 最低字段 | 目的 |
|---|---|---|
| specimen | 个体 ID、物种、性别/未知、群体/品系、倍性及证据 | 区分 HiFi A 与 Hi-C B；混样列出成员 |
| library | specimen ID、平台、建库方法/酶、文库 ID、lane、双端关系 | 技术重复与生物重复不混用；Omni-C 空酶有明确含义 |
| artifact | 文件内容摘要、格式、大小、生成步骤、角色、坐标所依赖 FASTA 摘要 | 文件路径和人类命名不等于数据身份 |
| assembly | 原始/清理/挂载/校正版本、primary/alternate/hap 角色、所属个体、父版本 | hap1 不自动命名为父本；保留未挂载序列 |
| run/stage | 固定源码 SHA、容器摘要/工具版本、完整参数、输入摘要、资源、退出码、日志 | 复现和判断重跑范围 |
| assessment | 被评 FASTA 摘要、reads 个体、数据库版本、方法、原始结果、限制 | 防止旧 QC 被贴到新 assembly |
| edit | 前后版本、坐标体系、拆分/翻转/连接/删除、证据、操作者、时间 | 人工校正和生物学取舍可审计 |

未知值保留为 unknown/null，不能生成看似完整的父母归属、核型或通过结论。大文件摘要可在登记时计算并缓存，但必须能识别文件随后被替换。

## 3. 阶段输入输出与验收

| 阶段 | 输入 → 必存输出 | 放行所需检查 |
|---|---|---|
| 输入登记 | reads/元数据 → 清单、校验摘要、QC | 格式可读、双端一致、个体关系和建库方法明确；覆盖度分母可追踪 |
| 基因组调查 | 合适的 reads → k-mer 直方图、模型/残差、估计 | 不只取一个 genome size 数字；峰、倍性假设和模型适配有记录 |
| 初组装 | 目标个体 reads → FASTA、GFA、日志、缓存和版本 | 非空合法序列、长度/命名统计；输出角色符合指定模式；报告基础 QC |
| purge/去污染 | assembly + 深度/比对/分类证据 → 保留和移除 FASTA、理由 | 不把完整 BUSCO 降低或独有可靠 k-mer 丢失隐藏；原始 assembly 可恢复 |
| polishing | assembly + 同个体适用 reads → 新 FASTA、改动表 | 相同方法前后比较；基因、QV、杂合位点/重复区检查；不默认多轮必然改善 |
| Hi-C 挂载 | 指定 FASTA + 正确处理的 Hi-C 比对 → FASTA、AGP、日志、接触图 | 染色体归组/次序/方向审查；未挂载序列保留；FASTA 与 AGP 重建一致 |
| 人工校正 | 接触图+多证据 → 新版本、edit 清单、未解决区域 | 每项改动可定位；导出后重建、重映射或可靠坐标转换，并重新评价 |
| 发布候选 | 最终 assembly + 全部证据 → 总报告、文件摘要、局限 | 必需 QC 齐全；按维度声明支持程度，不能只有 pipeline exit 0 |

阶段状态至少区分 pending/running/failed/computed/validated/reviewed。计算完成不等于生物学审查完成；可选结果缺失明确写 skipped/failed，不写零错误。

## 4. 坐标与缓存是正确性的组成部分

FASTA 经 purge、polish、拆分、翻转或挂载后，其衍生索引、BAM、BED、接触矩阵、注释都需要核对。纯重命名也可能使 contig ID 失配。可以用经过验证的坐标转换保留兼容数据，不能直接沿用旧 BAM 假装已对新参考比对。保存参考 FASTA 摘要与坐标版本。

自己的阶段缓存键应由规范序列化的输入内容摘要、参数、源码/容器版本及数据库身份构成；资源设置是否影响结果另行记录。Sanger 的 stage ID 与 Nextflow 任务缓存是不同层次，见20；不能仅凭 dataset ID 相同就宣称两批 reads 一样。

进程执行用参数数组，避免把样本名直接拼入 shell；确需 shell 的管道明确失败传播，保存标准错误和调度器日志。OOM/超时可按资源策略重试；输入损坏、样本不符、配置不兼容必须先修正。不要用 `|| touch result` 或 `|| echo done` 掩盖失败。必需结果既检查存在、非空和可解析，也检查生物学含义；stub 只验调度和交接。

## 5. 覆盖度、分型和质量报告

**用户指定最低HiFi覆盖50×，数据量是否足够为必报项。** 计算`coverage_x = effective_hifi_bases / haploid_genome_size_bp`；记录两项的来源、过滤规则和估计范围。评估同时保存`minimum_coverage_x=50`、达标/不足/待评估/估计范围跨阈值、有效数据缺口`max(0, 50*G-D)`。G范围为[Gmin,Gmax]时覆盖范围为[D/Gmax,D/Gmin]，不能仅选较小G宣称通过。调查后及初组装后均复核；小于50×的探索性初组装不算数据量验收通过。50×指D/G，二倍体不是每hap50×。该条为用户项目要求，不冒充EBP标准；多倍体另记录口径与目标，不因总量达标自动认定各hap足够。

覆盖度记录总有效碱基数、估计基因组长度和倍性口径。二倍体 D/G（G 为一套长度）与每个同源拷贝约 D/(2G) 的覆盖度不同；read depth、k-mer 峰、GenomeScope 参数也不直接等同。不能看到数字就自动乘二传 `--hom-cov`。Sanger 当前源码对 c 的用途见20。

每个 hap 单独评价，也评价两 hap 合集；primary/alternate 不要求等长。报告碱基准确度、k-mer/基因完整度、拷贝数、结构、分型、污染与连续性，不能以单一 N50 排名决定胜负。没有亲本/独立真值时，父母来源与 switch error 的定量结论要留空或注明方法限制。

## 6. 当前已有的可执行基础

在学习库根目录运行：

```bash
python3 tests/assembly_contracts/check_contracts.py
```

14 个合成案例复用已有严格 AGP/FASTA 检查器，覆盖正确拆分、反向互补、IUPAC、坐标/part 错误、遗漏/重复使用和序列不一致。结果见[validation.json](../tests/assembly_contracts/validation.json)。它适用于要求保留全部输入序列的 W-component 挂载契约，不是通用 AGP 2.1 全规范实现；主动删除、填缝、polish 应使用改动清单和相应守恒范围。它不能验证 Hi-C 推断出的染色体归组是否真实。

真正实施完整流程时，还必须做所选固定版的官方测试、阶段故障/恢复测试，以及目标物种真实数据验证。当前这些仍未完成。

## 7. 高标准质量策略入口

后续开发必须读取或明确落实[质量策略配置](../config/assembly_quality_policy.json)与[23验收表](23_EBP2026规范与本项目对标要求.md)，逐项报告外部基线、项目目标、观测值、证据独立性和适用性。不用一个总分抵消结构错误；缺失数据不通过。配置是本项目的设计文件，尚未接入实际流程或实现自动判定器，不能将它作为已执行的QC结果。
