# 组装格式转换与数据交接：SAM/BAM、FASTQ和GFA/FASTA

更新：2026-11-02。官方接口核对和可复用命令模板；除另附实测记录外，不声称执行过模板。转换是组装流程必备阶段，必须纳入版本、日志、样本及内容检查，不能只更改后缀。

## 1. SAM/BAM → FASTQ / FASTQ.gz

| 输入/用途 | 工具 | 要点 |
|---|---|---|
| 通用SAM/BAM/CRAM导出reads | samtools fastq；FASTA用samtools fasta | CRAM解码可能需要匹配参考；检查记录过滤、缺SEQ/QUAL和截断 |
| PacBio原生BAM/DataSet XML | pbtk的bam2fastq / bam2fasta | 支持多文件，默认输出gzip；`-o`是前缀；旧bam2fastx已归档迁移 |
| 已有FASTQ压缩 | gzip、pigz | 只是压缩，不改变read类型或提高准确度 |
| 只有FASTA想恢复FASTQ | 无法恢复原始质量 | 占位质量不是原始测量，不可当HiFi质量证据 |

单端HiFi示例（确认输入确为完整HiFi记录后使用）：

```bash
set -o pipefail
samtools fastq -@ 8 -n input.hifi.bam > sample.hifi.fastq
samtools fastq -@ 8 -n input.hifi.sam | gzip -c > sample.hifi.fastq.gz
# 安装的是pbtk提供的bam2fastq；默认生成sample.hifi.fastq.gz
bam2fastq -o sample.hifi input.hifi.bam
```

这三条展示替代选择，不应对同一输入重复导出后合并。压缩也可用`pigz -p 8 -c`。按samtools在线1.25手册，指定输出文件的.gz后缀支持自动压缩；stdout重定向`> x.gz`本身不会自动压缩，因此管道示例必须经过gzip/pigz。

若要在FASTQ头注释保留现有预测准确度与pass数，可在匹配版本下使用`samtools fastq -n -T rq,np input.bam`。`-T`仅复制标签，不执行筛选；FASTQ仍不是原BAM的等价备份。原BAM的read group、kinetics、甲基化和条形码等信息需要独立保存与专门消费者。

**格式不等于数据类别**：subreads/CLR转为FASTQ仍是subreads/CLR。适用平台的subreads产生CCS需共识计算；不能靠导出得到HiFi。读名含ccs也不能代替交付类型与质量检查。PacBio `extracthifi`按预测准确度筛选，并不完成subreads共识计算。详细来源、平台边界及旧仓库迁移见[官方接口复核](sources/read_format_conversion_review_2026-11-02.md)。

比对BAM还可能无法恢复完整原输入：samtools默认排除secondary/supplementary；hard-clipped碱基已不在记录中；缺QUAL可能产生占位质量。优先使用保存完好的原生HiFi BAM，不能把命令exit0当作无损恢复证明。

二代PE应另走按QNAME collate/name-sort后分别导出R1、R2、singleton和类别0，不要套单端命令后宣称配对不变。HiFi常属类别0，误用`-0 /dev/null`会丢弃它们。

## 2. hifiasm GFA → FASTA

通用工具与hifiasm作者示例的等价入口：

```bash
gfatools gfa2fa sample.bp.p_ctg.gfa > sample.primary.fa

# 对含实际序列的hifiasm contig GFA，可提取S记录
awk -F '\t' '$1=="S" {print ">"$2; print $3}' sample.bp.p_ctg.gfa > sample.primary.fa
```

第一条是gfatools官方子命令；第二条依据hifiasm官方README示例收紧为按tab解析S记录。实际运行前检查所有S行第三列非`*`，否则应拒绝导出而不是生成看似成功的FASTA。

选择文件比转换命令更重要：

| 常见输出 | 含义/使用方式 |
|---|---|
| `*.bp.p_ctg.gfa` | 仅HiFi默认模式primary contigs，适合需要一套代表序列的分支；不等于完整分相 |
| `*.bp.hap1.p_ctg.gfa` / `*.bp.hap2.p_ctg.gfa` | 仅HiFi模式的部分分相两套；分别导出和评价，不能宣称染色体级完整相位 |
| `*.hic.hap1.p_ctg.gfa` / `*.hic.hap2.p_ctg.gfa` | Hi-C模式两套contig图；仍需核查相位和后续染色体组织 |
| `*.dip.hap1.p_ctg.gfa` / `*.dip.hap2.p_ctg.gfa` | trio模式输出；亲本对应关系按实际输入和版本确认 |
| `*.r_utg.gfa` / `*.p_utg.gfa` | unitig图，某些图感知工具可用；不能不加说明替代最终contig组装 |
| `*noseq*.gfa` | 不含序列的简化图，不能凭空转出真实FASTA；部分工具可用其深度/图标签作辅助 |

名称与模式随实际版本/参数确认，不以glob把所有GFA转换后全部拼在一起。普通GFA的S记录只是图段：提取S记录并不自动沿P/W路径拼接染色体，也不处理重叠、方向或gap。上述contig导出适用于hifiasm相应contig图，不能无限推广所有图。

FASTA丢失图的连接、覆盖和reads归属信息。保留原GFA；后续HapHiC等可能需要与FASTA相匹配的GFA深度及hap归属。两hap联合挂载应有显式联合策略、唯一ID和预期染色体数，而非将primary/alternate/hap1/hap2全部混合。

依据：[hifiasm官方README](https://github.com/chhylp123/hifiasm)、[官方输出解释](https://hifiasm.readthedocs.io/en/latest/interpreting-output.html)、[gfatools](https://github.com/lh3/gfatools)。输出解释网页标题仍标0.16.0，不能当作已锁定当前版本全接口；当前README仅核对相关示例。

## 3. 交接检查与开发需求

转换阶段统一记录实际软件版本/构建或commit、完整命令、输入输出hash、样本和数据类型，写临时文件，成功并检查后才作为下游正式输入。

- FASTQ：gzip完整性、解析、read数/总碱基、序列与质量等长、ID冲突和预期过滤数量；用有效目标HiFi碱基重新计算用户要求的≥50×，不得用SAM记录数代替独立reads。
- FASTA：记录数、非空序列、合法碱基、唯一ID，与选定GFA的S序列数/总长/内容一致；拒绝`*`和无序列GFA。不能只检验文件非空。
- 相关工具：SeqKit可做FASTA/FASTQ统计与格式处理；samtools faidx可建索引供按区域访问，但索引成功不证明组装质量；压缩FASTA随机访问按下游要求选择bgzip及索引，普通gzip不自动等价。
- 失败传播：Bash管道启用pipefail，避免前端转换失败而压缩器成功留下空gzip；保留stderr，不删除原始BAM/GFA，不覆盖旧结果。

这些是流程开发契约，目前不是已经实现的通用格式适配器。

## 4. 本轮实际转换证据

已用本机samtools1.21对合成SAM/BAM执行导出，7项内容检查通过，见[实测记录](../tests/format_conversion_2026-11-02/README.md)。反向序列/质量恢复、附加比对过滤、标签导出、hard clipping、缺失QUAL及压缩输出均有保存。缺失QUAL的占位输出与按在线默认值推测不一致，初次失败保留且根因未确认；不能用自动生成的FASTQ质量证明HiFi准确度。这个实验不等于真实HiFi数据转换或组装验收。

另实际编译gfatools提交`39c54d5dfe4678d4cfb75b37bd27d4fb21f4de72`，验证含P路径的GFA仅导出2条S序列，2项内容断言通过。无序列`S ... *`人工输入触发本构建SIGSEGV（返回-11），属于已保存的失败观察；没有验证其他版本，也不把源码局部线索说成已确认完整根因。原始命令、源码归档、输入输出及哈希见同一[实测记录](../tests/format_conversion_2026-11-02/README.md)。这说明前检不能省略，noseq不能靠导出程序恢复真实序列。
