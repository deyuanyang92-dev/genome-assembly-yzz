## 2. 命令模板：HiFi-only与有二代时分别运行

以下从学习库根目录理解。输入均为实际FASTQ，参数需按样本、内存和倍性设置；软件应先安装到隔离环境并固定版本。模板经源代码接口核对，**没有在本机用真实reads执行**。

先统计，各文件分开输出，最后按同一数据集汇总sum_len；配对数据两端都计入：

```bash
seqkit stats -a -T /data/sample.hifi.fastq.gz > hifi.stats.tsv
seqkit stats -a -T /data/sample.R1.fastq.gz /data/sample.R2.fastq.gz > illumina.stats.tsv
```

普通GenomeScope2可用KMC生成两列frequency/count直方图。分别为HiFi、Illumina建立独立工作目录与输入清单，每行一个文件绝对路径。以下为单一数据集、k=21的示意：

```bash
# 在新建且专用于本次调查的目录操作；reads.list已由输入清单产生。
mkdir -p scratch result
kmc -k21 -t8 -m32 -ci1 -cs1000000 -cx1000000000 @reads.list survey.k21 scratch
kmc_tools transform survey.k21 histogram result/survey.k21.hist -cx1000000
Rscript /path/to/genome-assembly-yzz/pipelines/tbenavi1_genomescope2.0/genomescope.R \
  -i result/survey.k21.hist -o result/gs.k21 -k 21 -p 2 --json_report
```

上例显式使用二倍体模型；未知倍性不能仅凭默认值做最终结论。R脚本需要按上游安装其R包及minpack.lm/argparse/jsonlite等依赖，单有源码路径不够。再以独立前缀和输出目录运行k=31；图、summary、JSON与完整日志都保留在result，scratch不得兼作最终输出。GenomeScope有现成 `report.json`，后续开发应解析它，不重写拟合算法。

`-cs1000000`只是展示显式高上限的模板，不保证适合所有数据。KMC `-cs`是饱和上限；计数阶段 `-cx`排除超阈值k-mer；直方图阶段 `-cx`限制输出范围。记录最高频bin是否堆积、被排除部分和参数敏感性，必要时提高上限；不能用默认255截尾后无条件报告重复总量。默认canonical，勿加关闭canonical的 `-b`；FASTA输入需选择相应格式参数，不照搬FASTQ模板。

FastK/Smudgeplot是另一条链，当前版本不用旧版KMC `smudgeplot.py hetkmers`接口：

```bash
FastK -v -t4 -k31 -M16 -T4 /data/sample.hifi.fastq.gz -Nsurvey.fastk
# L必须从实际直方图选择；12只是演示值。
smudgeplot hetmers -L 12 -t 4 -o survey.pairs survey.fastk
smudgeplot all -o survey.smudge survey.pairs.smu
```

FastK `-t4`保留用于表的最低计数，与线程 `-T4`不同；下游-L不能恢复上游丢掉的数据。FastK表包括stub和隐藏分片，迁移时不能只拷贝`.ktab`。Histex的 `-G`有专门尾部处理，不能不核查就当普通GenomeScope直方图；需选官方匹配链（例如GENESCOPE.FK），不要混合格式/尾部口径。Smudgeplot当前C源码输出`prefix.smu`，README注释中`prefix_text.smu`与后续命令不一致，按当前源码核实。

LRGE作为另一种G估计，可按其固定版本帮助设置PacBio平台 `-P pb`；默认平台为ONT，默认抽样针对细菌，不能原样套大型真核。先确定目标规模对应的query/target抽样量和资源，再按README/论文的真核设置验证。当前1.0系列相对论文旧版修改了估计/区间定义，不能把当前结果当旧版论文复现。这里未提供一个未经大基因组验证的通用抽样参数。

## 3. 已找到的论文现成wrapper：为何不能直接生产使用

文件：`pipelines/mbhall88_lrge/paper/workflow/scripts/genomescope.py`，串联KMC→直方图→GenomeScope2，使用subprocess参数数组。但它是论文辅助脚本：

- 默认倍性1、计数最低2、计数上限255；动物二倍体及高覆盖重复调查必须重新设置。
- GenomeScope的最终输出写在 `--tmp`，默认末尾 `shutil.rmtree(tmpdir)` 会删除结果；`--no-cleanup`才能保留。
- `--tmp`若已存在会复用，最后仍递归删除；不得传入已有数据目录。脚本也没有为独占临时目录建立所有权验证。
- 输出前缀取文件名第一个点之前的部分，多样本可能冲突；默认log为整数2，日志处理也不适合作为生产接口。

本轮没有运行此wrapper处理真实样本。离线检查 `python3 tests/reads_survey_audit/audit_collected_sources.py` 使用mock的subprocess和独占TemporaryDirectory，两例确认默认删除最终结果、加保留参数则留存，并核实默认倍性/计数上限；见[验证记录](../tests/reads_survey_audit/validation.json)。**这是脚本行为验证，不是GenomeScope生物学准确度验证。** 保持上游源码不改，未来安全编排见29。
