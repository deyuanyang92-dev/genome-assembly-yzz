# 去冗余软件说明书与参数核查

2026-11-01。本轮覆盖purge_dups、Purge Haplotigs、Redundans、HaploMerger2及hifiasm内置去冗余；深度不等：前者有固定源码与7例提取行为验证，其他以官方文档/原始论文指定段落核查。没有真实样本去冗余实验，不宣称5种软件都已安装或全部源码已通读。新增上游仓库0，仍26个。

## 先区分想保留什么

等位haplotig冗余、末端异合重叠、真实串联/片段复制、转座元件/重复、性染色体、细胞器、污染、PCR重复是不同对象。去冗余不是去除生物学重复，read去重复也不是assembly purging。BUSCO D高或assembly大于G不能单独作为删除依据。

| 交付目标/输入 | 本项目决策 |
|---|---|
| 希望一套primary，存在残留等位双份区域 | 深度＋self-alignment＋k-mer拷贝/图证据支持后评估purge；保留不purge基线 |
| 已有完整hap1、hap2 | 不合并两套后压成一套；每hap检查异常，证据充分时局部处理，不能盲目全局purge |
| 近交/低杂合样本，单覆盖峰 | 自动拟合可能误判；先考虑不purge，人工核对峰及hifiasm模式 |
| 多倍体、近期WGD、扩张基因家族、高相似真实拷贝 | 二倍体模型不能直接套；不以压到G或降低BUSCO D作为成功 |
| 半合子/性染色体，局部半深度 | 半深度不等于haplotig，必须结合性别/核型/同源关系和唯一序列 |
| 非同个体reads或Hi-C | 不作为目标个体无偏WGS深度或相位真值；Hi-C不可代替常规WGS覆盖拟合 |

## purge_dups：优先集成候选，但不是强制步骤

本地提交f14dae13b7f41559bafd058f7278e8f5ac2813da。核查README、src/get_seqs.c、calcuts.c、opt.c及部分purge_dups.c；未逐行审完全部算法。方法论文：[Guan等，Bioinformatics 2020，btaa025](https://doi.org/10.1093/bioinformatics/btaa025)。工具结合read depth与序列相似识别haplotig及异合重叠。

标准交接：同个体WGS reads→映射到待purge的同版primary→PAF→pbcstat→PB.stat/PB.base.cov→calcuts/覆盖图审核；另一支split_fa→self PAF；两支汇合purge_dups→dups.bed→get_seqs→保留与移出FASTA→前后评价。

- HiFi映射用map-hifi；CLR用map-pb；ONT根据准确度与minimap2版本选适当ONT模式。self-alignment是asm5 -DP。二者不可混淆：asm20不等价于HiFi read mapping。
- 官方提醒大基因组设置足够的minimap2 -I确保单参考索引块，否则覆盖可能不正确。选择资源能容纳的索引并检查日志；reads分批后PAF合并不等于参考多索引块问题已解决。
- 保留全部同个体有效reads及明确映射规则，不为制造好看的双峰人为删reads。参考含primary还是两hap会改变峰；混合输入的竞争映射与多重命中计数也需验证。
- contig ID避免冒号等与split区间编码冲突的字符；记录ID转换，不随意更名后复用旧PAF。
- calcuts的-l/-m/-u分别定义低覆盖、中间转换与高覆盖边界，来自本样本直方图；不是G、HiFi50×门槛或通用固定比例。自动calcuts的cutoff文件是6列，不能把手工3个配置值直接当成该文件格式。
- 本地calcuts手工分支输出low,mid-1,mid-1,mid,mid,high；自动分支不同，保留原始文件和版本，不擅自重排或按另一版本重建。
- purge_dups -2表示两轮alignment chaining，不是连续运行两次全流程；-c在purge_dups是base coverage文件，在get_seqs却是保留HIGHCOV，必须按可执行程序区分。
- dups.bed分类含JUNK、HIGHCOV、HAPLOTIG、PRIMARY、REPEAT、OVLP、UNKNOWN；具体输出哪些由算法分支决定。标签是软件判断，不是生物学真值。输出.hap.fa可能包含低/高覆盖等移出序列，不能直接命名为“纯净完整hap2”。

### get_seqs的关键边界（固定版本源码＋合成检查）

| 参数/行为 | 含义及工程风险 |
|---|---|
| -e | 跳过内部候选区间并启用split输出；仍可能整条移出HAPLOTIG、JUNK、HIGHCOV，因此不是绝对防误删开关 |
| 不加-e | 允许处理内部候选；非split模式将保留的左右片段用23个N连接。不能误称为gap-free contig或已确定真实邻接 |
| -s | split输出；和-e不同，单独-s不会禁止内部删除 |
| -c | 保留被标记为HIGHCOV的整条contig到primary；不是保护所有类型重复，不解决塌缩，也不构成一概推荐 |
| -l，默认10000 | primary残余长度条件，源码使用严格大于；可能使候选区域以外的短残余也移出，不能只把BED长度当真实移出量 |
| -m，默认0.05 | 剩余primary占原contig比例条件；与上项共同决定提取，不是序列相似度 |
| -g，默认10000 | 合并相邻候选区间的距离；可能改变最终处理区间，必须核查原BED与实际输出差异 |
| -p | 输出前缀；默认purged.fa/hap.fa，设-p sample则sample.purged.fa/sample.hap.fa；在独立目录运行避免覆盖 |

核查中7个构造案例通过：内部区间-e保留、默认内部删除加23N、末端处理、整条HAPLOTIG/JUNK/HIGHCOV移出以及-c保留HIGHCOV。最初用总长度守恒的断言发现23N行为，读源码后改为原始碱基与新增N分别核算。见tests/purging_review；这只验证提取接口，不证明候选分类准确。

### 适配模板

仅在确认需要处理的一套primary上使用；没有真实样本运行。需先把minimap2、purge_dups与脚本放入隔离环境，单独运行目录，按实际基因组配置索引容量。

```bash
set -euo pipefail
minimap2 -x map-hifi -t 32 -I 8G primary.fa hifi.fastq.gz | gzip -c > reads.paf.gz
pbcstat reads.paf.gz
calcuts PB.stat > cutoffs.auto 2> calcuts.log
python3 "$PURGE_DUPS_DIR/scripts/hist_plot.py" -c cutoffs.auto PB.stat coverage.png
split_fa primary.fa > primary.split.fa
minimap2 -x asm5 -DP -t 32 -I 8G primary.split.fa primary.split.fa | gzip -c > self.paf.gz
# 审核coverage.png和cutoffs.auto后再决定是否执行，8G不是通用设置
purge_dups -2 -T cutoffs.auto -c PB.base.cov self.paf.gz > dups.bed 2> purge_dups.log
get_seqs -e -p trial dups.bed primary.fa
```

生产编排应在候选生成与提取之间分阶段，使异常/不确定阈值能够停止提取并保留结果；模板连续展示不代表开发时取消审核。自动阈值失效的常见原因是低杂合、无清晰双峰、不均匀覆盖、污染/细胞器、性染色体及多倍体。覆盖估计的目标个体和G也需单独验收。

## Purge Haplotigs：整contig重分配与人工审阅证据

原始官方仓库在[Bitbucket](https://bitbucket.org/mroachawri/purge_haplotigs/)，不是已核实存在的同名作者GitHub。该站本轮未读到完整最新手册；以下算法与阈值来自[Roach等2018原论文](https://doi.org/10.1186/s12859-018-2485-7)，命令由公开论文补充日志交叉核对。另读到skingan/purge_haplotigs_multiBAM分支README，该分支的旧比对/多BAM行为不可冒充当前上游实现。

三阶段：hist生成深度分布→cov用用户选定low/mid/high标记候选→purge用序列比对/冲突处理重分配contigs。需要FASTA和对应BAM，可选重复BED；depth模型要求相对无偏覆盖，论文提醒多重比对采用random best，而不是计入所有命中。映射预设按平台，坐标排序/index和secondary策略需匹配实际安装版。

原论文默认候选/artefact相关比例80%、重分配alignment score阈值70%、重复标记max match score250%，这些是不同统计量，不能写成70%identity或“比对长度250%就是真重复”。重复注释可从对应评分中排除重复区。应保留curated、haplotigs、artefacts和assignment表/冲突顺序/dotplot，而非仅保留primary。

它主要重分配整条contig，不能视为purge_dups末端重叠处理的等价替代。论文只测试二倍体，不能修复haplotype switch或保证得到两套完整相位染色体。例子阈值见37，不复制为默认值。完整CLI/版本安装及生物实测待完成。

## Redundans：序列相似/重叠驱动的缩减与附加组装步骤

官方入口已转到[Gabaldonlab/redundans](https://github.com/Gabaldonlab/redundans)，读README参数；[2016 NAR方法论文](https://doi.org/10.1093/nar/gkw294)本轮核对书目信息/摘要，未完成全文复现。

在线README列--identity默认0.51、--overlap默认0.80、--minLength默认200，支持--minimap2reduce以及--preset，另有--noreduction、--noscaffolding、--nogapclosing等模块控制。0.51是该工具配置事实，不是本项目认为相似51%就应该删除的标准；无固定commit时不能认为所有安装版相同。

它包含reduction、scaffolding、gap-closing，直接整套运行会引入多个变量，不能把之后N50增加全部归因于去冗余。只做purging对照时要显式关闭或隔离其他模块，核查真实调用命令和产物。精确模块间开关的完整组合需按安装版验证，本轮不提供未经运行的长命令。

序列相似本身难以区分真实片段复制和等位冗余。对高度相似基因家族/多倍体/相位保留项目应特别谨慎，不作为HiFi+hifiasm的默认后处理。README的“homozygous assembly”是输出表示目标，不表示生物材料变成纯合。

## HaploMerger2：重建两套表示，不等于现代长程分相

读[官方README](https://github.com/mapleforest/HaploMerger2)及[2017方法摘要](https://doi.org/10.1093/bioinformatics/btx220)。工具从已有高杂合二倍体组装推断等位关系，重建reference/alternative，并含纠错、层级挂载、补洞。摘要强调≥3%高杂合应用，但这不是唯一适用门槛或充分性保证。

官方manual.v3.4.pdf本轮尚未完整获取/阅读，因此不虚构全套batch脚本默认值或声称已掌握所有参数。HM2的两套sub-assembly不应直接等同于有亲本/Hi-C支持的两套全染色体hap；自比对难区分等位与高相似真实重复。2021独立比较发现部分组合过度缩减，详见37；不据单一物种断言工具永远不好。

## hifiasm内置purging与外部purge如何区别

本地0.25.0-r726，ec9a8b222d149d25b7355e83765698640d59b189；CommandLines.cpp、参数/FAQ指定段落。-l 0不purge，1轻，2/3更积极；当前CLI列trio默认0、unzip默认3，不能把所有模式都写成3。-s是read层面的重复相似阈值，不是purge_dups calcuts中间深度；--purge-max影响primary相关处理，提高可能塌缩重复/片段复制；--hom-cov是覆盖估计，不是直接删到某长度。

内置与外部不是完全等价：图/read信息、覆盖模型和产品角色不同。默认先记录当前组装模式和已有内置处理；若外部再做，要用不处理基线及证据证明收益。-l0也不能当成外部purge的普遍前置要求，不同工作流确有不同设计，见37。
